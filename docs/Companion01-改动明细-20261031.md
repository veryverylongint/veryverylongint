## 一、改动清单（按代码语义）

### 1. 出屏通道与体积通道解耦

**改前**（两通道抢同一份 step 预算，`popCM` 被 `stepCen=0` 架空，只剩 `focusSlice` 微调）：

```swift
let stepVol = stepShift / perspComp
let stepCen: Float = 0
off = unitIdx * n1F * stepShift * halfW_d
shift = -off / halfW_zero - centerShift        // halfW_zero 里含 focusSlice
```

**改后**（`stepCen` 独立计算，直接进 `shift`，不再挤占体积预算）：

```swift
let stepVol = stepShift / perspComp
let stepCen: Float = viewMode == 1
    ? Float(2.0 * effCen / cells)               // 模式 A：不设上限
    : min(Float(2.0 * effCen / cells), 0.05)    // 模式 B：上限 0.05
off         = unitIdx * n1F * stepShift * halfW_d
centerShift = -unitIdx * n1F * stepCen
shift       = -off / halfW_d - centerShift      // 注意：分母从 halfW_zero 改回 halfW_d
shift       = clamp(shift, -1.0, 1.0)           // 内容不出画
```

### 2. 上限按模式分离

**改前**：`maxStepShift = min(0.026·强度, 0.28/(N−1))` —— 28 是拍出来的，N 小时会把深度锁死。

**改后**：

```swift
let maxStepShift: Float = viewMode == 1
    ? 0.111                                     // 模式 A：80 px/步（帕农融合极限）
    : min((extreme ? 0.045 : 0.026) * rlMul, 0.36 / max(1.0, n1F))
```

`0.111 NDC = 80 px`：70 cm 处约 4 mm 屏上视差，对应出屏 3.5–4 cm（人眼可融合上限）。

### 3. 模式切换（按钮「模式 B→A」）

```swift
viewMode == 1 时：views=4,  volCM=4.0, popCM=8.0     // 跳变突出预设
viewMode == 0 时：views=20, volCM=2.2, popCM=1.5     // 稳定移动预设
```

### 4. 拖动降采样 4 台 → 2 台

```swift
// 改前：isDragging ? max(every, 4) : every      （4 台，跨 4 个视点插值）
// 改后：isDragging ? max(every, 2) : every      （2 台）
```

原因：`every=4` 时，插值会在相邻 4 个视点之间做线性混合，模型的高对比边缘被平均成两条位置——这正是**拖动时"偏移重影"、停下后恢复**的来源。

### 5. UI 重排

| 相机 | 视点数、焦距mm |
| 交织 | 实渲间隔、相位偏移 |

| 按钮行 | 载入最新、选文件、监控文件夹、标定体、轴向、模式 B→A |

同时修正了三个**滑杆初值与渲染器不一致**的 bug（`扇区Z°` 初值写死 90 而默认已是 40，一碰就跳变；`观看距离` 写死 0.7）。

## 二、三个现象的成因分析

### 现象 1：移动/旋转时偏移重影，静止才恢复

**已定位**：拖动期间启用 `every=4`，即只渲 5 台相机、其余由 shader 做 1D 线性插值：

```metal
int a = choice / every, b = min(a + 1, camCount - 1);
float w = float(choice - a * every) / every;
rgb[ch] = mix(camA[ch], camB[ch], w);
```

当 `every=4` 时，相邻两次采样相隔 4 个视点，插值出的中间视点是**两幅图的叠加**；高对比度轮廓在两幅图上位置不同 → 叠成"双影"。停下后 `every` 回到 1，20 台全渲 → 重影消失。

**已改**：拖动时降到 `every=2`（10 台，跨 2 视点）。代价是拖动帧时间从 ~0.14 s 升到 ~0.25 s。若仍嫌卡，正确方向是**减少每帧相机数同时关闭插值**（`w` 取 0 或 1，直接切最近相机），而不是加大插值跨度。

### 现象 2：体积cm 拉高变清晰，拉低反而有重影和拉伸感

与"体积越大越糊"的直觉相反，需要解释。三个候选机制（尚需实验区分）：

**机制 A（最可能）——低体积时视差小于色度收敛半径**
当前交织对色度做了「向中心视点收敛 70%」的处理。体积小时 `stepShift` 只有 1–2 px，相邻视点的亮度差极小，但色度被强行拉向中心视点 → 亮度与色度在小尺度上错位 → 表现为**细碎的彩色重影**。体积拉大后视差超过这个尺度，色度差本身变大，反而"各归各位"，看起来更干净。

**机制 B——低体积时紧贴零视差面**
`focusSlice = −0.25`，零视差面贴着模型前部。体积小时几乎整个模型都挤在零视差面附近 → 所有表面都落在"微视差区" → 透镜无法分辨相邻视点 → 糊成一片，同时因透视正确而显得"被拉伸"。

**机制 C——`tanh` 软饱和的副作用**
体积小时 `rawStepShift << maxStepShift`，`tanh` 近似线性；体积大时进入饱和区，斜率变小 → 大体积段的观感变化变缓，用户感觉"拉高才清晰"。

**建议验证**：固定 `volCM=0.5`，分别把「单视点诊断」开关打一次、把 `立体强度` 从 0.3 拉到 4，看"重影"是否随强度消失。若消失 → 机制 A/C；若不变 → 机制 B。

### 现象 3：A/B 切换"就像拉体积的效果一样"

模式 A 与 B 的差异应该体现在四件事上，但如果只看到"深度变了"，说明差异没有全部生效：

| 应是 | 实际可能 |
|---|---|
| 视点数 20 → 4（方向数骤减） | ✅ 生效 |
| 单步 10.7 px → 66–80 px | ✅ 生效（但用户感知为"体积变大"） |
| 每视点 0.98 → 4.9 子像素（彩边消失，画面变锐） | ❓ 需要确认 |
| 移动变成跳格 | ❓ 需要确认 |

**它看起来"就像拉体积"是合理的**：A 与 B 的主要可见差异确实是视差量级，而"跳格/锐利"只有**移动头部**时才明显。若静止观察，两者都只是深度不同的同一画面。

要真正体现"模式"差异，可以：

1. 模式 A 时**把 `every` 锁为 1**，并把立体强度默认再推高；
2. 在 UI 上直接显示当前步长（`每步 10.7 px / 66 px`），让差异可读；
3. 加"静止 A / 移动 B"自动切换（移动时才用 B 的平滑），但会引入切换闪烁，不建议。

## 四、待外部模型确认的问题

1. **现象 2 到底是 A/B/C 哪个机制**？有没有更简单的判别实验？
2. **拖动期降采样**：`every=2` + 线性插值仍会混两幅图。是否应改成"最近邻切换（不做插值）+ 每帧只渲 N/2 台"？这在视觉上会比插值更跳，但不会有双影。
3. **模式 A 的 N=4 是否足够？** 每视点 4.91 子像素，但透镜 PSF 会混入相邻 2–3 个子像素——实际彩边是否真的为 0？
4. **模式 B 的 `focusSlice=−0.25` 是否该随 volCM 联动**？现在固定，导致小体积时整模型挤在零视差面附近（推测是"拉伸感"来源）。
5. 模式 A/B 是否应该合并成一个连续旋钮（视点数 + 扇面），而不是两个离散模式？
