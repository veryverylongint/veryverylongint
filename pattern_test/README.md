# Companion-01 相机测试：专用图样 + OBS 分析

## 为什么这样设计

相机可能**歪、有反光、每次位置不同**，所以：

- 每张图样四角都印了 **96 px 品红标记**。分析脚本用它们解单应矩阵，把任意拍摄角度拉正回 1440×2560 面板坐标再取样——歪 20°、斜着放都不影响判读。
- 图样只用**大面积、纯色、少细节**的内容。60 cm 距离、720p 相机下，1 个面板像素≈0.5 个相机像素，细线条必然糊掉；能判的只有"整块的颜色/亮度"和"视点号"。
- 反光被当成局部亮度偏移处理：判据看的是**屏内离散度**，不是绝对亮度。

## 运行

```bash
open PatternTest.app          # 或 ./PatternTest
```

- 控制窗出现在电脑主屏；输出窗自动铺满面板（1440×2560，1:1，已自检）。
- 按钮 `0`–`10` 切图样；三个滑杆实时改 `lineNumber / obliquity / deviation`；勾「自动轮播」每 5 秒换一张。
- 命令行离屏渲染：`./PatternTest --dump 9 out.png`

## 每张图样回答什么

| # | 图样 | 判据 | 说明 |
|---|---|---|---|
| 0 | 灰场 | 反光位置/亮度基线 | 反光会在固定位置发亮 |
| 1 | 黑场 | 反光最明显 | 只用来找反光源，不判 3D |
| 2 | 白场 | 亮度均匀性 | 边角暗 = 视角衰减 |
| 3 | 视点色相 | **屏内应单一颜色**；移动相机应连续变色 | 出现固定彩虹条纹 = 交错错 |
| 4 | 视点灰阶 | 同上，读数更稳 | 相机对亮度比色度线性 |
| 5 | 视点二进制条 | **直接读出视点号**（6 条 = 0–39） | 最硬的证据 |
| 6 | 零视差 | 应完全平，任何位置不变 | 重影/双线 = 串扰或错相 |
| 7 | 左右眼错位 | 奇偶视点左右跳 | 判左右与串扰 |
| 8 | 三档视差 | 三段位置跳变 | 判视点是否真被分开 |
| 9 | 深度三色条 | 红(前)/绿(屏)/蓝(后) | **判深度方向**：相机右移，红条应左滑 |
| 10 | 几何 1:1 | 边框/刻度/中心十字 | 查是否 1:1、有无缩放 |

## 拍摄

1. 屏固定好，镜头对准屏心，距离 **50–80 cm**；歪 10–20° 可以接受。
2. OBS：720p 或 1080p、30 fps。**务必关掉自动曝光/自动白平衡/自动对焦**——否则亮度差会被自动增益吃掉，判读失效。
3. 勾「自动轮播」，录 40–60 秒，同时**相机缓慢左右平移 ±10 cm**。这一步是判"视点有没有真的切换"的关键，静止不动看不出差别是正常的。
4. 想单独验某张图样，就手动点到那张，录 5 秒。

## 分析

```bash
python3 analyze_obs.py 录像.mov --scale 720
```

- 需要 numpy。系统 python 没有的话用 Hermes 自带的：
  `/Users/notverylongint/.hermes/tools/python-3.14.9+*/bin/python3`
- 输出：终端报告 + `report/report.json` + 每段一张代表帧 `seg_XX.png`。

## 判读

| 读数 | 含义 |
|---|---|
| 视点读数固定不变 | 相机没移动，或交错没生效 / 整屏重复同一视点 |
| 视点读数随移动跳变 | quilt 视点序生效（方向对不对还要看第 9 张） |
| 屏内色相离散 < 40° | 该位置基本只看到一个视点，相位是对的 |
| 屏内色相离散 > 40° | 同时看到多个视点：串扰/相位差，拖 deviation 重测 |
| 角标残差 > 3 px | 相机太歪或画面裁掉了角，换位置重拍 |
| 时间抖动大 | 自动曝光没关 |

方向判读：**相机向右移动时，前景（红条）应向左滑**（像透过窗户看外面）；蓝条同向。反了就是视点序反了。
